# TV 视觉与交互设计笔记

## 参考对象

- Jellyfin 官网展示的产品截图强调：首页突出媒体库和海报；详情页承载媒体信息；播放页给出播放和投屏等控制。
- Emby Android TV 文档强调 Android TV 设备和遥控器场景，同时把播放兼容性放在 direct play、转码和码率策略上。
- Infuse 官方定位是优雅的视频播放器，围绕海报、artwork、metadata 和播放控制建立高级感；Firecore release notes 在 tvOS 8.2.5 引入 Liquid Glass design，8.2.7 继续更新 player controls 外观。本项目的 Infuse 主题不复制 Apple 私有组件，而提炼为深黑舞台、半透明玻璃 surface、冷蓝高光、轻量控制层和海报优先的信息架构。

## Infuse 主题审计

- 全局：Infuse 主题必须切换完整颜色系统，包括背景、surface、raised surface、control、input、poster fallback、边框、overlay、文字和焦点色；不能只改焦点色。
- 首页：媒体海报是第一视觉，标题遮罩使用主题 overlay，焦点环和标题底条用冷蓝高光表达选中；工具区保持紧凑，不能变成大面积按钮墙。
- 详情页：左海报、右信息仍保持稳定比例；metadata 和技术信息使用主题化 pill，减少硬编码灰蓝边框，让 Infuse 的玻璃感贯穿详情决策区。
- 设置页：主题 OptionSelect 第一屏可见，Infuse 主题文案说明“深黑舞台与冷蓝玻璃高光”，帮助用户理解这是视觉模式而非协议模式。
- 播放器：黑底全屏仍优先；视频信息面板、快捷 seek 反馈和控制区辅助按钮使用主题 overlay / focus ring，不常驻遮挡内容。
- 登录 / 错误 / 空状态：沿用同一套 surface、input、focus token；这些页面不应单独写死颜色，否则切换 Infuse 后会显得割裂。

## 详情页原则

- 不直接展示协议字段，例如 `EPISODE`、`MOVIE`、原始 ticks 或接口内部枚举。
- 元信息使用用户语言：`单集`、`电影`、`约 24 分钟`、`第 1 季 / 第 5 集`。
- 播放动作优先于长简介，保证从详情到播放的路径短。
- 详情页首个“播放 / 继续播放”使用主按钮视觉，常态就应比从头播放、低码率、字幕样式和倍速更突出；次级动作不放大，避免首屏操作区变成一排同权重按钮。
- 间距应对称：左侧海报、右侧信息和按钮保持稳定边距，不让标题或海报把操作挤出首屏。
- 长标题必须保护信息首行，不允许标题遮挡元信息；详情页媒体标题放在海报右侧内容区，最多三行后截断，元信息和播放按钮始终在标题下方正常排布。
- 技术信息属于次级信息，用小号 metadata pill 展示，不和播放按钮争主视觉。
- 技术信息优先整理成观看决策语言：分辨率、视频编码、HDR / 杜比视界、位深、音频编码、声道、杜比全景声、容器、大小、码率、字幕数量、字幕语言、字幕格式、默认字幕、外挂字幕、强制字幕，以及 HEVC / AV1 / 杜比视界、高码率、高清音频和图形字幕的兼容性 / 转码风险提示。
- 字幕技术信息必须合并展示：数量和语言放在同一枚标签，格式和外挂字幕放在同一枚标签，默认字幕、强制字幕和图形字幕转码风险放在同一枚提示标签，避免字幕 metadata 把详情页撑散。
- 兼容性提示只能表达“依赖设备或转码”“可能触发转码”这类观看风险，不能在没有设备级 codec 探测时写成当前设备确定支持或不支持。

## Design tokens

- 颜色集中在 `TvColors`：背景、surface、焦点、强调色、正文色和弱文本色都从这里引用。
- `TvColors.applyTheme` 必须覆盖完整 palette。新增主题时至少定义 background、surface、surfaceRaised、surfaceControl、surfaceInput、posterFallback、posterBorder、focus、focusRing、focusText、accent、accentStrong、resume、textPrimary、textSecondary、textMuted、pillBorder 和 overlay。
- 间距集中在 `TvSpacing`：页面左右边距、section 间距、按钮间距、海报间距和播放器浮层边距不在页面里临时写死。
- 字号集中在 `TvType`：品牌、标题、section、正文、元信息、卡片标题和播放器标题分别固定尺度。
- 尺寸集中在 `TvSize`：按钮高度、输入框高度、首页海报、详情海报和播放器浮层高度统一管理。
- 圆角集中在 `TvRadius`：按钮与卡片只使用少量稳定圆角，避免每个页面各画各的。
- 电视端 320dpi 下首页海报不能沿用手机/平板的大卡片尺度；当前首页海报基准为 `118x177dp`，横向间距 `10dp`，让首屏更容易同时看到多个媒体库或媒体项。
- 遥控器焦点必须远距离可见：按钮焦点使用高对比填充、内部焦点环和轻微抬升；海报卡片焦点同时改变描边和标题底条颜色，避免用户找不到当前焦点。
- 遥控器焦点不能通过放大组件来制造选中感；焦点边框应画在组件原始边界内，配合颜色、阴影和短过渡动画表达状态，避免边框比原元素更大导致裁切。
- 返回不作为普通页面的常驻按钮。详情页、搜索页、字幕样式、播放速度等页面依赖遥控器 Back 返回上一层；只有错误恢复这类需要明确选择恢复路径的页面可以展示返回动作。
- 错误恢复页必须按上下文给出一个明确主动作：播放失败优先低码率重试，会话过期优先重新登录，普通浏览错误优先回到仍可用的首页；恢复动作使用统一竖向动作组，保持稳定间距和初始焦点。诊断信息是次级动作，但需要独立信息图标。诊断页内的导出和分享也必须使用下载 / 分享图标，导出优先，导出完成后分享优先，并和返回动作放在同一竖向动作组里。
- TV 信息密度默认偏紧凑：减少全局加粗文字，优先用尺寸、位置、颜色和焦点态表达层级，避免每个设置项都占据一整行。
- 详情页的元信息和技术信息 tags 必须自动换行展示，不能藏在横向滚动容器里。
- 详情页的媒体源、音轨和字幕选择使用类似 Jellyfin / Emby 的 OptionSelect：页面上只展示“字段名 + 当前值”的摘要行，按确认后打开 popover 选择列表，当前项在列表里带勾；选择轨道只改变播放偏好，不额外打开整页二级选择页。轨道选择必须基于当前 playback info 规范化，旧 media source 或 stream index 不存在时回退到服务器默认，避免把一个版本的字幕套到另一个版本上；详情页轨道选择不使用带圆点的 RadioSelect，也不把所有选项平铺在详情页。
- 详情页所有可聚焦控件都应使用同一套垂直 D-pad 滚动兜底：能移动到下一个按钮或 OptionSelect 摘要行时交给焦点系统，已经到达可聚焦控件边缘时才滚动外层页面。播放按钮、媒体源、音轨和字幕摘要行不能各自写特殊规则，也不能把用户困在某个按钮附近。
- 焦点态必须有短过渡动画，但不能通过放大组件表达选中，避免焦点环超出原边界后被父容器裁切。

## 播放器原则

- 播放器必须是黑底全屏 surface，不能嵌在普通页面或滚动容器中。
- 进入播放器后默认焦点给 Media3 PlayerView，让遥控器优先控制播放、暂停和 seek。
- OK / Enter 是播放器最高频的播放状态切换：按下后直接暂停或恢复，不要求用户先呼出控制层再找播放按钮。
- 遥控器左右键是播放器最高频的快捷 seek：控制层隐藏时左键后退 30 秒，右键前进 30 秒；控制层已经显示时左右键交给 Media3 进度条 / 设置焦点处理，避免抢掉用户正在操作的控件。
- OK / Enter 和硬件播放 / 暂停键直接切换播放状态；暂停时必须呼出 Media3 控制层和时间轴，原生播放 / 暂停图标保持可见并获得焦点，让再次按 OK 能直接恢复播放，而不是误触字幕、设置或视频信息。
- 左右快捷 seek 必须给出轻量文字反馈，例如“+30 秒”“-30 秒”，并同时呼出 Media3 时间轴；连续左右键仍保持快捷 seek，不因为时间轴出现就突然切换成控制条焦点导航。
- 播放器不叠加第二套 app 级播放按钮。Media3 控制层保留原生播放 / 暂停图标和时间轴，但不展示重复的快退和快进按钮；播放 / 暂停、seek、进度条和控制显隐交给遥控器快捷键与 Media3 原生控制层分工处理。
- “视频信息”入口必须插入 `exo_settings` 所在的 Media3 `exo_basic_controls` 控制行，贴近右下角设置按钮，和原生控制层共用同一套焦点树；不能再作为播放器外层 root 的独立按钮，否则暂停 / 恢复时容易把焦点兜到右下角。
- App 层只负责系统 Back 退出播放并回到详情页；诊断入口随 Media3 控制层显示，不常驻遮挡画面。
- Back 属于高风险退出动作，第一次只用 Toast 提醒“再次按返回退出播放”，短时间内第二次 Back 才停止播放并回到详情页；不使用弹窗，不替换播放器画面，也不叠加第二套播放控制。
- 字幕样式属于播放前偏好，不在播放器画面常驻展示；详情页提供“字幕样式”入口，设置字号、颜色和背景后持久化到本机，并在播放器创建时应用到 Media3 `SubtitleView`。字幕设置页必须用横向单选式紧凑控件提高密度，不能把每个选项都做成全宽大按钮，也不能用“已选”前缀撑大按钮；重建页面后焦点要回到刚操作的字号、颜色或背景选项组，避免遥控器连续调整时跳回顶部。每组选项使用统一的设置行容器，当前值由单选态表达，不额外显示重复状态文本；恢复默认使用图标动作。
- 播放速度属于一次性播放偏好，使用横向单选式紧凑选项组，默认焦点放在 1.0x，避免用户进入页面后先落在非常规倍速；选中状态由单选控件表达，不使用“已选”前缀。播放速度和字幕样式共享同一套设置行组件，避免设置页视觉碎片化。

## 登录原则

- 登录页 public users 使用紧凑头像行：左侧 44dp 头像，右侧显示用户名和“需要密码 / 免密码登录”状态，整行作为一个遥控器焦点目标；无头像或加载失败时不阻断登录。用户行获得 / 失去焦点时使用短过渡动画改变填充、内部描边和轻微层级，不能瞬间跳色或通过放大组件表达选中。
- 认证页主动作必须有明确层级和图标：连接服务器、登录、立即检查授权使用主图标按钮；继续账号、最近服务器、清除登录、Quick Connect 和返回动作使用次级图标按钮，避免首次使用路径出现一串同权重文字按钮。
- Quick Connect 授权码不是普通说明文案，应使用高对比等宽代码块显示，让用户在 TV 距离下能快速抄到 Jellyfin 端。
- 服务器入口页要把最近账号和最近服务器分成带标题的竖向动作组；用户先看到可继续登录的账号，再看到仅保存过地址的服务器，最后才是手动输入地址。

## 首页原则

- 首页首屏优先露出媒体内容，不让搜索输入长期占据主视觉。
- 媒体项以横向海报架为主，焦点卡片使用内部描边、标题底条变色和短过渡动画表达选中；标题底条和焦点环都要平滑过渡，避免 D-pad 移动时出现僵硬跳变。
- 搜索、刷新、切换账号、设置、退出等全局动作放在顶部工具区，并配合图标减少阅读成本；退出放在最后，设置用于承载主题和后续全局偏好，切换账号不等同于退出登录。
- 全局设置页第一屏保持轻量，先提供主题 OptionSelect。主题是本机偏好，选择后立即应用并持久化；后续字幕默认样式、默认播放策略等全局偏好可以继续收敛到设置页，但不能把首页变成表单入口。
- 首页空状态不能只是一句说明文字；提示附近必须提供最常用恢复动作，优先是刷新，其次是搜索媒体和切换账号，初始焦点直接落在主动作上。
- 首页有媒体内容时必须始终有可见焦点：优先恢复 `TvAppState.focus` 对应的媒体卡片；如果该 item 因刷新、搜索或分页已经不存在，则把焦点落到首个可用媒体卡片，而不是停在无焦点状态。用户用遥控器移动到新的媒体卡片时，要立刻更新 `TvAppState.focus`，让详情返回和播放返回都回到刚停留的位置。
- 搜索页筛选使用统一设置行里的横向单选式紧凑选项，不做大块表单，也不使用“已选”前缀；切换全部 / 电影 / 剧集 / 单集 / 视频时必须保留用户已经输入的搜索词，避免遥控器重复打字。
- 搜索结果页要和普通首页区分；无结果时主动作是重新搜索，且回到搜索输入时保留当前搜索词，次级动作再提供返回首页和切换账号。
- 搜索页语音输入使用系统语音识别，不自建录音 UI；识别成功后直接按当前筛选搜索，取消或设备没有语音服务时回到搜索页并保留原输入。
